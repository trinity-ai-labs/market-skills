# Financial Model — example product

Three live rows, none of them a defect, and the middle one is the reason this
vault exists. `model-row-dead-assumption` read the row→note direction as a
question about `type` when it is a question about `status`, so a row backed by a
`current` claim was reported as a row standing on a retired note — every word of
the message true and the conclusion wrong.

Row A-1 is backed by a `claim` and by nothing else: no `assumption` in this
vault carries its title. Row A-2 is the ordinary side, backed by a `current`
assumption that declares itself a model input. Row A-3 is the promotion shape
verbatim — the assumption behind it was retired and a `claim` carrying the same
title replaced it, which is what this method prescribes for a structural driver
with no subject instrument, and what the check was calling a defect.

The two counts in the success line disagree here on purpose: three rows against
two declared model inputs, because a row backed by a `claim` is not a declared
input and never becomes one.
